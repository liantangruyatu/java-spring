# 城市公共设施智能报修与状态监控平台 - 项目文档

## 第一部分：需求分析

### 1.1 项目背景
随着城市化的推进，城市公共设施数量急剧增加，如何高效地进行管理和维护成为城市管理的重要课题。传统的报修方式存在信息不对称、处理流程不清晰、无法及时跟进等问题。本项目旨在建立一个完整的智能化报修与监控系统，实现设施资产的全生命周期管理。

### 1.2 项目目标
1. 提供便捷的移动报修渠道，让市民能随时随地报修
2. 实现报修工单的全流程自动化管理
3. 提供数据化的设施监控与分析
4. 优化维修资源配置，提高服务效率

### 1.3 主要功能需求

#### 1.3.1 公共设施管理
- 设施基础信息录入（编号、类型、位置、坐标、状态）
- 设施分类管理（路灯、公园长椅、公共厕所、健身器材）
- 设施状态跟踪（正常、损坏、维修中、已报废）
- 设施地理位置标注与可视化

#### 1.3.2 用户管理
- **市民用户**：手机号注册、登录、查看和提交报修单
- **维修工**：接收分配任务、处理报修、反馈维修结果
- **管理员**：系统监管、数据分析、预警处理

#### 1.3.3 报修单管理
- 市民在线提交报修（上传图片、详细描述）
- 报修单自动分配给任务量最少的维修工
- 维修工接单、开始维修、完成维修的全流程
- 报修单状态实时查询与跟踪

#### 1.3.4 智能分配与预警
- **自动分配**：新报修单自动分配给待办任务最少的维修工
- **超时预警**：维修中超过48小时的设施向管理员发出预警
- **通知机制**：实时通知维修工、管理员重要信息

#### 1.3.5 统计与分析
- 各类型设施的故障率统计
- 平均维修耗时计算
- 维修工效能评估
- 时间序列数据分析

### 1.4 非功能需求
| 需求 | 要求 |
|-----|-----|
| 性能 | 支持至少1000个并发用户 |
| 可用性 | 系统可用性 > 99% |
| 数据安全 | 密码加密、SQL注入防护 |
| 响应时间 | 平均响应时间 < 2秒 |
| 可扩展性 | 支持模块化扩展 |

### 2.5 关键业务流程

#### 报修流程
```
市民提交报修单
    ↓
系统自动分配给任务最少的维修工
    ↓
维修工接收通知并接单
    ↓
维修工开始维修（设施状态变为"维修中"）
    ↓
维修工完成维修并提交反馈
    ↓
报修单标记为"已完成"
    ↓
设施状态恢复为"正常"
```

#### 预警流程
```
每小时定时检查报修单
    ↓
发现状态为"维修中"且超过48小时的报修单
    ↓
系统自动创建"超时预警"
    ↓
向对应管理员发送预警通知
    ↓
管理员可在系统中查看并处理预警
```

### 3.2 维修工自动分配算法

```java
// 关键逻辑: 在WorkerServiceImpl中
public Worker assignRepairOrder(Long repairOrderId) {
    // 1. 查询所有可用的维修工，按待办任务数升序排列
    List<Worker> availableWorkers = workerRepository
        .findWorkerWithLeastPendingTasks();
    
    // 2. 获取任务最少的维修工
    Worker worker = availableWorkers.get(0);
    
    // 3. 分配报修单
    RepairOrder order = repairOrderRepository.findById(repairOrderId);
    order.setWorkerId(worker.getUserId());
    order.setStatus(ACCEPTED);
    
    // 4. 更新维修工待办任务数
    worker.setPendingCount(worker.getPendingCount() + 1);
    return workerRepository.save(worker);
}
```

### 3.3 超时预警实现

```java
// 在AlarmServiceImpl中的定时检查方法
public void checkAndCreateTimeoutAlarms() {
    // 1. 查询所有维修中的报修单
    List<RepairOrder> processingOrders = 
        repairOrderRepository.findAll()
            .stream()
            .filter(ro -> ro.getStatus() == PROCESSING)
            .collect(Collectors.toList());
    
    // 2. 检查是否超过阈值(48小时)
    LocalDateTime threshold = LocalDateTime.now().minusHours(48);
    
    // 3. 对超时单据创建预警
    for (RepairOrder order : processingOrders) {
        if (order.getSubmitTime().isBefore(threshold)) {
            alarmRepository.save(
                new Alarm(order.getId(), "timeout_repair", ..., HIGH)
            );
        }
    }
}
```

### 3.4 统计计算逻辑

**故障率计算：**
```
故障率 = (故障设施数 / 总设施数) × 100%
按设施类型分别统计
```

**平均维修耗时：**
```
平均维修耗时 = Σ(完成时间 - 提交时间) / 完成的报修单数
单位: 小时
```

### 4.1 环境要求
- JDK 8+
- MySQL 8.0+
- Node.js 14+
- Npm or Yarn

### 4.2 数据库初始化
```bash
# 1. 创建数据库并导入初始化脚本
mysql -u root -p < docs/init.sql

# 2. 配置数据库连接
编辑 facility-repair-backend/src/main/resources/application.yml

```

### 4.3 后端启动
```bash
cd facility-repair-backend
mvn clean package
java -jar target/facility-repair-system-1.0.0.jar
```

```bash
cd facility-repair-frontend
npm install
npm run dev
# 访问 http://localhost:5173
```
